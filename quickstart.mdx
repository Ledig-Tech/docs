---
title: "Quickstart"
description: "Set up your API key and make your first request."
---

This guide starts with a balance read, so you can check your connection and authentication before creating a payment.

<Steps>
  <Step title="Get access">
    Request a business account through [ledig.io](https://www.ledig.io/contact) and complete onboarding. Contact [support@ledig.io](mailto:support@ledig.io) for sandbox access.
  </Step>
  <Step title="Create an API key">
    Ask your business administrator to create an API key in the dashboard. For this example, the key needs the `balances:read` permission or read-only access. Save the secret when it is shown; you cannot view it again.
  </Step>
  <Step title="Choose Sandbox">
    Set the API URL:

    ```bash
    export LEDIG_API_BASE_URL="https://sandbox.ledig.io"
    ```

    Add `LEDIG_API_KEY` and `LEDIG_API_SECRET` to your application's server-side secret configuration. Use your sandbox credentials.
  </Step>
  <Step title="Check the connection">
    The health endpoint does not require authentication:

    ```bash
    : "${LEDIG_API_BASE_URL:?Choose your API URL first}"
    curl --fail-with-body "${LEDIG_API_BASE_URL%/}/v1/health"
    ```

    A successful response is:

    ```json
    { "status": "ok" }
    ```

  </Step>
  <Step title="Read your USD balance">
    Use the [Node.js or Python authentication example](/auth/authentication#examples) to call `GET /v1/balances/USD`. It calculates a fresh signature and sends the required headers for you.

    The balance fields in a successful response look like this. These are fictional amounts:

    ```json
    {
      "currency": "USD",
      "available": "1250.00",
      "reserved": "100.00"
    }
    ```

    `available` is the amount you can use. `reserved` is set aside for payments in progress. See [Balances](/guides/balances) for the full response and balance behaviour.
  </Step>
  <Step title="Build your payment flow">
    Follow [Funding](/guides/funding) to receive money or [Quotes](/guides/quotes) to convert currencies and send payments. Test the flows your application needs before switching to [Live](/introduction#environments).
  </Step>
</Steps>

If a request fails, use [Errors and troubleshooting](/errors/errors-and-troubleshooting). If a payment request times out, follow the [retry rules](/guides/idempotency) to avoid creating a duplicate.
