---
title: "Quickstart"
description: "Configure access and make a first signed read request."
---

<Steps>
  <Step title="Confirm your environment and business">
    Request access through [ledig.io](https://www.ledig.io/contact). Agree the approved integration environment and business with Ledig. Read [Environments](/introduction#environments) before testing.
  </Step>
  <Step title="Create an API key">
    An authorised business administrator creates a key in the dashboard. Select only the permissions the integration needs. Keep the API key and secret in server-side secret storage; the secret is shown once.
  </Step>
  <Step title="Set the API origin">
    Set `LEDIG_API_BASE_URL` to the approved HTTPS origin, without a trailing path. Configure `LEDIG_API_KEY` and `LEDIG_API_SECRET` securely. Do not paste credentials into source files or command history.
  </Step>
  <Step title="Check connectivity">
    The public health route needs no signature:

    ```bash
    : "${LEDIG_API_BASE_URL:?Set the approved API origin first}"
    curl --fail-with-body "${LEDIG_API_BASE_URL%/}/v1/health"
    ```

    A healthy process returns `{ "status": "ok" }`. This checks API reachability, not database access, service eligibility or payment readiness.

  </Step>
  <Step title="Make a signed read">
    Use the runnable examples in [Authentication](/auth/authentication#examples) to call `GET /v1/balances`. Sign the exact method, path with query, timestamp and body sent. Never put the secret into a request header.
  </Step>
  <Step title="Choose your workflow">
    Discover currencies with `GET /v1/currencies`. Follow [Funding](/guides/funding) for receiving accounts and addresses, or [Quotes](/guides/quotes) for conversion and payout pricing. Complete an approved test scenario before enabling payment writes in your application.
  </Step>
</Steps>

Use [Errors and troubleshooting](/errors/errors-and-troubleshooting) when a request fails. A timeout on a write is an unknown outcome, not permission to submit a replacement payment.
