Use the payments API to receive funds, check balances, convert currencies and send payments. Choose an endpoint from the sidebar to see the fields it accepts and the responses your application should handle.

## Environment and authentication

Choose your API URL:

| Environment | API URL |
| --- | --- |
| Sandbox | `https://api-sandbox.ledig.io` |
| Live | `https://api.ledig.io` |

Send requests from your server using an API key for that environment. The [authentication examples](/auth/authentication#examples) show how to calculate the signature and timestamp for each request.

Some endpoints also accept a bearer token, as shown in their authorization section. Use one authentication method per request.

## Read an endpoint

| Section | What it tells you |
| --- | --- |
| Method and path | The URL to call and whether to use `GET`, `POST` or another method. |
| Required scope | The permission your API key needs. |
| Authorization | The authentication headers to send. |
| Request | The path, query and body fields you can send. |
| Response | The fields returned, with fictional examples. |
| Errors | The errors your application should handle. |

Amounts are usually decimal strings, such as `"1250.00"`. Use decimal arithmetic for financial calculations. Keep IDs and pagination cursors exactly as returned.

## Recommended flow

1. Read `GET /v1/currencies` to find supported currencies and networks.
2. Set up [funding](/guides/funding) and check your [balances](/guides/balances).
3. Save a [recipient](/guides/recipients), or confirm the ID of the Ledig business you want to pay.
4. Check the available [payment methods, fees](/guides/quotes#discover-payment-methods-and-fees) and [limits](/guides/limits).
5. Create a [quote](/guides/quotes), review its rate and fees, then confirm it with a [transfer](/guides/transfers).
6. Track the transfer and read your [transaction history](/guides/transactions).

If you manage other businesses, start with [Managed businesses](/guides/managed-businesses) for onboarding and selecting the business you are acting for.

## Handling responses

Use the [error guide](/errors/errors-and-troubleshooting) to handle failures and the [retry guide](/guides/idempotency) to recover from a lost response. Read [Webhooks](/hooks/webhooks) for event notifications.
